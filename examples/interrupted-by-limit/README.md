# Interrupted by a rate limit

1. In Claude Code, the user asks for a three-step plan (write `hello.py`,
   run it, add a failing check) and step 1 only. Claude writes `hello.py`.
2. Next prompt: run `python3 hello.py` (exit 0), then
   `python3 -c "raise SystemExit(7)"` (exit 7), and stop.
3. Before Claude can finish its reply, the account hits its usage limit.
   Claude Code's `StopFailure` hook fires with `error: "rate_limit"`, so the
   save becomes **interrupted** (`rate_limit in Claude Code`), not paused.
   The user quits.
4. Three minutes later Codex starts in the same folder. Its SessionStart
   hook gives it the save, which says the task was cut off by a rate limit,
   and the save records the handoff (`claude-code` to `codex`).

**What is real here and what is not.** The rate limit is built from the
documented payload shape, not from a real recording of one: no real
rate-limit `StopFailure` has been recorded yet. That one event is the real
`StopFailure` payload (recorded with `error: "authentication_failed"`) with
`error` changed to `"rate_limit"`, the value Claude Code documents for a
rate limit, and a limit message as its last reply. Every other hook payload
is a real Claude Code or Codex recording from `tests/fixtures/`. The
`/compact` that followed in the recording is left out.
`scripts/build-examples.py` (`rate_limited`) makes exactly these changes.
