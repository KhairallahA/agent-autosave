# One-key switch: Claude Code runs out, Codex carries on

The user runs `agent-autosave go claude-code codex` and works in Claude
Code.

1. Claude Code is asked for a three-step plan (write `hello.py`, run it,
   add a failing check) and step 1 only. It writes `hello.py`.
2. Before the next prompt, Claude Code's status line reports 88% of the
   5-hour limit used. `agent-autosave statusline` records the reading; it
   is past `handoff.warn_at_percent` (85).
3. So the next prompt (run `hello.py`, then a command that exits 7) comes
   with one ask, in [`ask.txt`](ask.txt): record a handoff note. Claude
   runs `agent-autosave note "..." --type handoff`, runs both commands, and
   is cut off by its usage limit: `StopFailure` with `error: "rate_limit"`.
4. Claude Code exits. `go` reads the save, sees the rate limit and asks
   once, in [`go.txt`](go.txt). Enter starts Codex with the resume block as
   its first prompt: the plan, the failing command and the handoff note.

**What is real here and what is not.** Every hook payload is a real Claude
Code or Codex recording from `tests/fixtures/`, as in
[interrupted-by-limit](../interrupted-by-limit/README.md), which has the
same rate limit built from the documented shape. Added by
`scripts/build-examples.py` (`near_limit`): the 88% status line reading,
in the fields Claude Code documents for status line commands, and the
handoff note the agent was asked for. `go.txt` is rebuilt by `replay.py`
from the ledger with `go`'s own functions.
